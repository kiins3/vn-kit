# vn-kit

[![CI](https://github.com/kiins3/vn-kit/actions/workflows/ci.yml/badge.svg)](https://github.com/kiins3/vn-kit/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)

Vietnam's administrative units for Java and Spring Boot, **up to date with the 2025 reform**:
34 provinces and centrally run cities, 3,321 wards, communes and special zones, no district level.

- **Plain Java core** with no dependencies: look up by code, find a province or ward the way people type it (`"tp.hcm"`, `"P. Ba Dinh"`, `"Hòa Khánh"`).
- **Old addresses converted**: `"P. Dịch Vọng, Q. Cầu Giấy, Hà Nội"` becomes `"Phường Cầu Giấy, Thành phố Hà Nội"`, with all 63 old provinces, 696 districts and 10,035 wards, and a clear flag when an old ward was split.
- **Phone numbers, citizen IDs (CCCD) and tax codes (MST)**: parse, normalize and validate, with the 2026 mobile prefixes and the 2025 switch to ID numbers as personal tax codes.
- **Spring Boot starter**: `@ProvinceCode`, `@WardCode`, `@WardInProvince`, `@ValidPhoneNumber`, `@ValidCitizenId` and `@ValidTaxCode` for Bean Validation, plus an optional REST API for address pickers.
- **Data you can trace**: generated by a script from a pinned release of an open dataset, and checked by tests (34 provinces, 3,321 units, 9 centrally run cities).

> Tiếng Việt: thư viện Java tra cứu tỉnh/thành và phường/xã **sau sáp nhập 2025** (34 tỉnh, 3.321 xã),
> tìm theo tên có dấu hoặc không dấu, **đổi địa chỉ cũ (63 tỉnh, quận/huyện) sang địa chỉ mới**,
> **kiểm tra số điện thoại, CCCD, mã số thuế**, kèm annotation validate cho Spring Boot và API
> cho dropdown chọn địa chỉ.

## Why

On 1 July 2025 Vietnam merged its 63 provinces into 34 and removed the district level; wards
and communes went from about 10,000 to 3,321. In 2026 Đồng Nai, Quảng Ninh and Bắc
Ninh became centrally run cities. Most Java code still carries the old three-level lists.
Python and JavaScript have updated libraries; Java did not.

## Install

Requires Java 17+. Not on Maven Central yet; until then, build it with `mvn install`.

```xml
<!-- Plain Java -->
<dependency>
  <groupId>io.github.kiins3</groupId>
  <artifactId>vn-kit-core</artifactId>
  <version>0.1.0-SNAPSHOT</version>
</dependency>

<!-- Spring Boot 3 (includes the core) -->
<dependency>
  <groupId>io.github.kiins3</groupId>
  <artifactId>vn-kit-spring-boot-starter</artifactId>
  <version>0.1.0-SNAPSHOT</version>
</dependency>
```

## Use

```java
AdminUnits.provinces();                       // 34 provinces, ordered by code
AdminUnits.province("79");                    // Optional[Thành phố Hồ Chí Minh]
AdminUnits.ward("26743");                     // Optional[Phường Bến Thành]
AdminUnits.wardsOf("01");                     // the 126 wards and communes of Hà Nội

AdminUnits.findProvince("tp.hcm");            // Thành phố Hồ Chí Minh
AdminUnits.findProvince("Thừa Thiên Huế");    // Thành phố Huế
AdminUnits.findWard("P. Ba Dinh", "Ha Noi");  // Phường Ba Đình
AdminUnits.searchWards("hoa binh");           // every Hoà Bình in the country, best match first

Ward w = AdminUnits.ward("26743").orElseThrow();
w.type();                                     // WARD (or COMMUNE, SPECIAL_ZONE)
w.province().fullName();                      // "Thành phố Hồ Chí Minh"
w.postalCode();                               // "71009"

VnText.removeAccents("Đà Nẵng");              // "Da Nang"
```

### How names are matched

People type names in many ways, so matching ignores case, punctuation, the unit type
(`Phường`, `P.`, `Xã`, `TP.`, `Tỉnh`) and the two styles of tone placement (`Hoà` = `Hòa`).
Accents are optional but **decide when they are the only difference**: Quảng Ngãi has both
Xã Sơn Hà and Xã Sơn Hạ, and Đồng Tháp has Phường Mỹ Tho and Xã Mỹ Thọ.

- `findWard` returns a unit only when the match is unambiguous: `"Sơn Hạ"` and
  `"xa my tho"` resolve, `"son ha"` does not.
- `searchWards` returns every candidate: exact matches first, then names that start with the
  query, then names that contain it.

## Converting old addresses

```java
Conversion c = AddressConverter.convert("12 Trần Thái Tông, P. Dịch Vọng, Q. Cầu Giấy, Hà Nội").orElseThrow();
c.address();      // "12 Trần Thái Tông, Phường Cầu Giấy, Thành phố Hà Nội"
c.exact();        // false: Dịch Vọng was split
c.candidates();   // [Phường Cầu Giấy, Phường Nghĩa Đô], the part with most of it first

AddressConverter.convert("Phường 12", "Quận Tân Bình", "TP.HCM");  // fields from a database
AddressConverter.convertProvince("Bình Dương");                   // Thành phố Hồ Chí Minh
AddressConverter.convertCode("26971");                            // by the old ward code
LegacyUnits.findDistrict("Q.1", "TP.HCM");                       // the old units themselves
```

What to expect:

- **Most old wards went whole into one current unit**: the result is exact.
- **471 old wards were split between several.** `ward()` is the one that received most of it
  (by location) and `candidates()` lists all of them. Only the street can tell which is right, so
  check `exact()` before saving a converted address without review.
- **Nothing rather than a guess.** Ten districts of Hồ Chí Minh City had a Phường 1, so
  `"Phường 1, TP.HCM"` returns empty; with the district it converts.
- The island districts that had no wards (Côn Đảo, Lý Sơn, Bạch Long Vĩ, Cồn Cỏ, Hoàng Sa)
  convert to their special zones.
- Old codes are not current codes: the old Bắc Ninh was `27`, the current one (merged with Bắc
  Giang) is `24`. Keep them apart in your database.

Tests convert every one of the 10,035 old wards from its own address, both as fields and as one
line.

## Phone numbers, citizen IDs and tax codes

```java
PhoneNumber p = PhoneNumber.parse("+84 912-345-678").orElseThrow();
p.national();     // "0912345678"
p.e164();         // "+84912345678"
p.formatted();    // "0912 345 678"
p.carrier();      // Optional[VINAPHONE]

PhoneNumber.convert("0168 812 3456");   // 0388123456: old 11-digit numbers from before 2018

CitizenId id = CitizenId.parse("079090001234").orElseThrow();
id.birthProvince().name();   // "Hồ Chí Minh"
id.gender();                 // MALE
id.birthYear();              // 1990
id.masked();                 // "079*******34", also what toString() prints

TaxCode.parse("0100109106-001").map(TaxCode::type);   // DEPENDENT
TaxCode.parse("0100109107");                          // empty: wrong check digit
```

| | Accepted | Checked |
| --- | --- | --- |
| `PhoneNumber` | spaces, dots, hyphens, brackets; `+84`, `84` or `0084` | mobile prefix assigned to a network, including `095` (Viettel) and `075` (Pottel) from 2026; fixed lines `02x` with 11 digits |
| `CitizenId` | 12 digits, spaces ignored | province code, gender and century digit, birth year not in the future |
| `TaxCode` | 10 digits, 13 digits with or without the hyphen, or 12 | check digit; 12 digits must be a valid `CitizenId`, the tax code of individuals since 1 July 2025 |

Only the structure can be checked offline: a number can be well formed and still not exist.
Since 2018 a subscriber can switch network and keep the number, so `carrier()` is the network
that issued it.

## Spring Boot

### Validation

```java
@WardInProvince(ward = "wardCode", province = "provinceCode")
public record AddressForm(
    @NotBlank @ProvinceCode String provinceCode,
    @NotBlank @WardCode String wardCode,
    @NotBlank String street) {}
```

| Request | Error |
| --- | --- |
| `provinceCode = "00"` | `provinceCode: is not a known province code` |
| `wardCode = "99999"` | `wardCode: is not a known ward or commune code` |
| `provinceCode = "79"`, `wardCode = "00004"` (in Hà Nội) | `wardCode: is not in the selected province` |

```java
public record CustomerForm(
    @NotBlank @ValidPhoneNumber(PhoneType.MOBILE) String phone,
    @ValidCitizenId String citizenId,
    @ValidTaxCode({TaxCodeType.MAIN, TaxCodeType.DEPENDENT}) String companyTaxCode) {}
```

`@ValidPhoneNumber` takes mobile and fixed lines by default, `@ValidTaxCode` all three kinds.
The validators accept what users type (`"091 234 5678"`); store the normalized form, e.g.
`PhoneNumber.parse(form.phone()).orElseThrow().national()`.

Messages ship in English and Vietnamese (`vi`) and can be overridden with the keys
`io.github.kiins3.vnkit.ProvinceCode.message`, `...WardCode.message`,
`...WardInProvince.message`, `...ValidPhoneNumber.message`, `...ValidCitizenId.message` and
`...ValidTaxCode.message` in your `ValidationMessages.properties`.

### REST API for address pickers

Off by default. Turn it on with:

```properties
vnkit.web.enabled=true
# vnkit.web.base-path=/api/vn
# vnkit.web.max-results=50
# vnkit.web.cache-max-age=1d
```

| Endpoint | Returns |
| --- | --- |
| `GET /api/vn/provinces` | all provinces |
| `GET /api/vn/provinces/{code}` | one province, `404` if unknown |
| `GET /api/vn/provinces/{code}/wards` | its wards, communes and special zones |
| `GET /api/vn/wards/{code}` | one ward |
| `GET /api/vn/wards?q=ben thanh&province=79&limit=10` | search by name; `province` can be a code or a name |
| `GET /api/vn/convert?address=P. Dịch Vọng, Q. Cầu Giấy, Hà Nội` | an old address converted, `404` if it cannot be identified |
| `GET /api/vn/convert?ward=Phường 12&district=Tân Bình&province=TP.HCM` | the same from separate fields |

```json
{ "code": "26743", "provinceCode": "79", "name": "Bến Thành", "nameEn": "Ben Thanh",
  "fullName": "Phường Bến Thành", "fullNameEn": "Ben Thanh Ward", "codeName": "ben_thanh",
  "type": "WARD", "postalCode": "71009" }
```

Responses carry `Cache-Control` because the data only changes when you upgrade the library.

## Data

The tables in `vn-kit-core/src/main/resources` are generated by
[`scripts/build_data.py`](scripts/build_data.py) from pinned commits of two MIT-licensed datasets:

- Current units: [thanglequoc/vietnamese-provinces-database](https://github.com/thanglequoc/vietnamese-provinces-database),
  which follows the national list of administrative unit codes and the resolutions of the
  National Assembly Standing Committee. The release and the latest resolution included are
  available at runtime from `AdminUnits.datasetVersion()` and `AdminUnits.latestDecree()`.
- Old units and how they map to current ones: [tranngocminhhieu/vietnamadminunits](https://github.com/tranngocminhhieu/vietnamadminunits).
  The script checks that every target exists in the current data, and names always come from the
  current data, so a ward that later became a phường shows its current name.

To update: bump `SOURCE_COMMIT` or `LEGACY_COMMIT` in the script, run
`python scripts/build_data.py`, and run the tests. CI fails if the bundled tables differ from
what the script produces.
